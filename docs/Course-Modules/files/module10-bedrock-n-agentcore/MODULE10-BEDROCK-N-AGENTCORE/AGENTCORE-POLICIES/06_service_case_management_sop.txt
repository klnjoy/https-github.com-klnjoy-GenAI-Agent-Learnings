Document Title: Service Case Management SOP
Document Type: Standard Operating Procedure
Department: Customer Operations
Version: 1.0
Effective Date: 2026-07-01

Purpose
This SOP defines when and how AI agents should create service cases for banking operations.

Case Types
Approved service case types include:
- transaction_dispute
- fee_review
- human_review
- loan_callback
- general_support
- fraud_review

When to Create a Case
Create a service case when:
- Customer requests a transaction dispute.
- Customer asks for late fee review.
- Customer asks for refund or reversal.
- Customer asks for loan assistance.
- Customer reports suspicious activity.
- Customer request requires human decision.
- Agent cannot complete the request safely.

Case Summary Requirements
Every case summary should include:
- Customer request
- Relevant transaction ID if available
- Policy reason for escalation
- Action requested from operations team
- Any important restrictions

Case Creation Rules
AI agents may create service cases only through approved tools.
AI agents must not create cases with restricted case types such as:
- refund_approved
- fee_waived
- account_modified

Status Values
Common case status values:
- created
- under_review
- pending_customer_input
- resolved
- rejected

Agent Response After Case Creation
After creating a case, the agent should:
- Share the case ID.
- Explain the next action.
- Avoid promising the final outcome.
- Keep the response professional and clear.

Sample Case Summary for Dispute
"Customer reported duplicate transaction from City Electronics. Transaction ID TXN9004. Dispute case created for operations review."

Sample Case Summary for Fee Review
"Customer requested review of credit card late fee. Transaction ID TXN9002. Fee review case created. Agent did not promise waiver."

Sample Case Summary for Refund Request
"Customer requested refund. AI agent cannot approve refund. Human review case created for operations validation."
