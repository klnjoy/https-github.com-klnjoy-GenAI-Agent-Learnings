Document Title: Transaction Dispute Policy
Document Type: Banking Policy
Department: Dispute Operations
Version: 1.0
Effective Date: 2026-07-01

Purpose
This document defines the policy for raising transaction disputes for unauthorized, duplicate, failed-but-debited, incorrect merchant, or incorrect amount transactions.

Policy Overview
A transaction dispute can be raised when the customer reports a suspicious or incorrect transaction. Common dispute reasons include:
- Duplicate transaction
- Unauthorized transaction
- Failed transaction where money was debited
- Incorrect merchant charge
- Incorrect transaction amount
- Goods or services not received after payment

Eligibility Criteria
A transaction dispute case may be created if:
- The transaction belongs to the customer.
- The transaction is posted, settled, or successfully debited.
- The transaction is generally within 30 days of the dispute request.
- The customer identity/KYC is verified.
- The customer provides a clear dispute reason.

Duplicate Transaction Rules
For duplicate transaction complaints:
- Search for transactions with the same merchant or similar amount.
- Verify if the transaction description suggests duplicate debit or repeated merchant charge.
- Create a transaction dispute case if the customer confirms the duplicate charge.
- Do not promise refund.

Agent Allowed Actions
AI agents may:
- Search transaction history.
- Explain the dispute process.
- Create a transaction dispute case.
- Provide the generated case ID.
- Mention that the dispute operations team will review the issue.

Restricted Actions
AI agents must not:
- Approve refunds.
- Reverse transactions.
- Modify transaction records.
- Guarantee that the dispute will be accepted.
- State that money will definitely be returned.

Recommended Customer Response
For duplicate or unauthorized transaction requests, the agent should confirm that a dispute case has been created and explain that the operations team will investigate. The agent should not promise refund or final approval.

Escalation Rules
Escalate to dispute operations if:
- Transaction amount is high.
- Customer reports fraud.
- Customer is high risk.
- Multiple suspicious transactions are found.
- The customer demands immediate reversal.

Sample Case Summary
"Customer reported duplicate POS debit from City Electronics. Transaction appears settled. Dispute case created for operations review."
