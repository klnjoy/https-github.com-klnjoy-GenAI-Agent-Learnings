Document Title: Customer KYC and Verification Policy
Document Type: Banking Policy
Department: Compliance Operations
Version: 1.0
Effective Date: 2026-07-01

Purpose
This document defines how customer verification status should be used when AI agents support banking requests.

Policy Overview
KYC status indicates whether the customer's identity has been verified according to bank compliance requirements. KYC status affects whether certain requests can be processed or escalated.

KYC Status Values
Common customer KYC status values:
- verified
- pending
- expired
- rejected
- unknown

General Rules
If KYC status is verified:
- The agent may proceed with eligible read-only and case-creation actions.
- The agent may create dispute, fee review, or human review cases if policy allows.

If KYC status is pending, expired, rejected, or unknown:
- The agent should not proceed with sensitive requests.
- The agent should ask the customer to complete KYC or contact support.
- The agent may create a general support case if needed.

Agent Allowed Actions
AI agents may:
- Read KYC status through approved customer profile tools.
- Use KYC status as a decision factor.
- Explain that KYC verification is required for certain banking actions.

Restricted Actions
AI agents must not:
- Modify KYC status.
- Approve KYC.
- Reject KYC.
- Ask the customer to share sensitive documents in chat unless the official bank channel supports it.
- Reveal sensitive verification details beyond what is needed.

Security and Compliance Note
KYC-related information should be treated as sensitive customer information. Responses should be minimal, professional, and policy-compliant.

Sample Response
"Your profile shows that KYC verification is required before this request can be processed. Please complete verification through the official banking channel."
